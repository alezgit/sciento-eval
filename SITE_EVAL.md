# SITE_EVAL.md — ScientoAI Expert Evaluation Site Guide

> **Goal**: Host one static HTML page per `(author, output)` pair on GitHub Pages.
> Each page reproduces the exact CSS of the ScientoAI Shiny app so experts see the
> output exactly as the application would show it — no navigation to other authors,
> no branding beyond the ScientoAI visual language.
>
> **Stack**: Pure HTML + CSS (no framework). Python build script to convert `.md`
> outputs into HTML files. GitHub Pages for hosting (one repo, ~16 URLs).

---

## 1. What the `.md` Output Files Look Like

When you click **"Download .md"** inside the app, the file has this exact structure:

```markdown
# Narrative CV: Professor Name
_Generated on: 2025-06-12_

## Thematic Research Areas

### Theme Name A
Description of the theme.

**Keywords**: keyword1, keyword2, keyword3

**Key Publications**:
- Paper Title (2023)
- Paper Title (2021)

### Theme Name B
...

---

## Academic Biography

[Long narrative text with Markdown formatting: ## headings, **bold**, bullet lists, etc.]
```

The file has two major sections above the `---` separator:
- **Thematic Research Areas** — one `###` block per cluster
- **Academic Biography** — the free-form narrative CV text

```
sciento-eval/          ← GitHub repo root
```

Google Fonts, which loads from the internet). The expert receives a single URL like:

```

```

```html
    // RAW MARKDOWN — replaced by the build script (build.py)
    // ================================================================
    const RAW_MD = `{{MARKDOWN_CONTENT}}`;

    // ================================================================
    // PARSER: splits the .md file into its two structural sections
    // ================================================================
    function parseMD(md) {
      const result = { title: "", themes: [], biography: "" };

      // 1. Extract title from first "# " line
      const titleMatch = md.match(/^#\s+(.+)$/m);
      if (titleMatch) {
        result.title = titleMatch[1].replace(/^Narrative CV:\s*/i, "").trim();
      }

      // 2. Split on the hr separator (---) that divides themes from biography
      //    The .md structure is:
      //      ## Thematic Research Areas   ← above the ---
      //      ---
      //      ## Academic Biography        ← below the ---
      const hrIndex = md.indexOf("\n---\n");
      const themeSection  = hrIndex !== -1 ? md.slice(0, hrIndex)     : md;
      const bioSection    = hrIndex !== -1 ? md.slice(hrIndex + 5)    : "";

      // 3. Parse themes: each ### block is one theme
      const themeBlocks = themeSection.split(/^###\s+/m).slice(1); // drop pre-header
      result.themes = themeBlocks.map(block => {
        const lines = block.split("\n");
        const name = lines[0].trim();

        const descMatch   = block.match(/^(?!###)([^*\n][^\n]*)\n/m);
        const kwMatch     = block.match(/\*\*Keywords\*\*:\s*(.+)/);
        const pubsMatch   = block.match(/\*\*Key Publications\*\*:\n([\s\S]*?)(?=\n##|\n###|\n\*\*|$)/);

        const description = descMatch  ? descMatch[1].trim()  : "";
        const keywords    = kwMatch    ? kwMatch[1].split(",").map(k => k.trim()).filter(Boolean) : [];
        const pubs        = pubsMatch
          ? pubsMatch[1].split("\n").map(l => l.replace(/^-\s*/, "").trim()).filter(Boolean)
          : [];

        return { name, description, keywords, pubs };
      });

      // 4. Biography is everything after the --- and the ## Academic Biography heading
      const bioBody = bioSection.replace(/^##\s+Academic Biography\s*\n/m, "").trim();
      result.biography = bioBody;

      return result;
    }

    // ================================================================
    // RENDER
    // ================================================================
    function render(md) {
      const data = parseMD(md);

      // Author name in profile card
      document.getElementById("author-name").textContent = data.title || "Professor";
      document.title = "ScientoAI — " + (data.title || "Narrative CV");

      // Theme cards
      const grid = document.getElementById("themes-grid");
      const section = document.getElementById("themes-section");
      if (data.themes.length === 0) {
        section.style.display = "none";
      } else {
        grid.innerHTML = data.themes.map(t => `
          <div class="cv-cluster-card">
            <h3>${escHtml(t.name)}</h3>
            <p>${escHtml(t.description)}</p>
            <div>${t.keywords.map(k => `<span class="cv-keyword-badge">${escHtml(k)}</span>`).join("")}</div>
            ${t.pubs.length > 0 ? `<ul class="cv-pubs-list">${t.pubs.map(p => `<li>${escHtml(p)}</li>`).join("")}</ul>` : ""}
          </div>
        `).join("");
      }

      // Narrative biography (rendered as Markdown → HTML)
      document.getElementById("narrative-body").innerHTML =
        marked.parse(data.biography || "");
    }

    function escHtml(str) {
      return str
        .replace(/&/g, "&amp;")
        .replace(/</g, "&lt;")
        .replace(/>/g, "&gt;")
        .replace(/"/g, "&quot;");
    }

    // Run on load
    render(RAW_MD);
  </script>
</body>
```

## 4. The Python Build Script (`build.py`)

This script reads a folder of `.md` files and generates one HTML file per input.

### Folder layout expected by the script

```
build/
├── template.html          ← the template above
├── md/
│   ├── author1_A.md       ← Output A for Author 1
│   ├── author1_B.md       ← Output B for Author 1
│   ├── author2_A.md
│   ├── author2_B.md
│   └── ...
└── out/                   ← generated HTML files go here (script creates it)
    ├── author1_A.html
    ├── author1_B.html
    └── ...
```

### `build.py`

```python
#!/usr/bin/env python3
"""
build.py — Generate ScientoAI evaluation HTML files from .md outputs.

Usage:
    python build.py

Reads:  build/md/*.md
Reads:  build/template.html
Writes: build/out/*.html  (one per .md, same stem)
"""

import os
import re
import pathlib

TEMPLATE_PATH = pathlib.Path("build/template.html")
MD_DIR        = pathlib.Path("build/md")
OUT_DIR       = pathlib.Path("build/out")

PLACEHOLDER = "{{MARKDOWN_CONTENT}}"


def escape_for_js_template_literal(text: str) -> str:
    """
    The MD content is embedded inside a JS template literal (`...`).
    We need to escape backticks and backslash sequences so the JS
    parser does not break.
    """
    # Escape backslashes first (order matters)
    text = text.replace("\\", "\\\\")
    # Escape backticks (they would close the template literal)
    text = text.replace("`", "\\`")
    # Escape ${...} which JS would try to interpolate
    text = text.replace("${", "\\${")
    return text


def build_all():
    OUT_DIR.mkdir(parents=True, exist_ok=True)

    template = TEMPLATE_PATH.read_text(encoding="utf-8")

    if PLACEHOLDER not in template:
        raise ValueError(f"Placeholder '{PLACEHOLDER}' not found in template.html")

    md_files = sorted(MD_DIR.glob("*.md"))
    if not md_files:
        print(f"No .md files found in {MD_DIR}. Nothing to build.")
        return

    for md_path in md_files:
        md_content = md_path.read_text(encoding="utf-8")
        escaped    = escape_for_js_template_literal(md_content)
        html       = template.replace(PLACEHOLDER, escaped)

        out_path   = OUT_DIR / (md_path.stem + ".html")
        out_path.write_text(html, encoding="utf-8")
        print(f"  ✓  {md_path.name}  →  {out_path}")

    print(f"\nDone. {len(md_files)} files written to {OUT_DIR}/")


if __name__ == "__main__":
    build_all()
```

### Run the script

```bash
# From the project root (where build.py lives):
python build.py
```

## 5. Step-by-Step Workflow

### Step 1 — Generate `.md` files from the app

For each author, run the app twice (once per orchestration mode):

1. Load the author's Scopus data.
2. Set **Orchestration** → `Sequential Pipeline`.
3. Click **Generate Narrative CV**.
4. Click **Download .md**.
5. Save as `build/md/authorX_A.md`.
6. Repeat with **Swarm Council** → save as `build/md/authorX_B.md`.

> **Naming convention**: use any consistent names (letters, digits, underscores).
> The HTML file will have the same stem, e.g. `smith_sequential.md` →
> `smith_sequential.html`.

### Step 2 — Run the build script

```bash
python build.py
```

Check the `build/out/` folder. Open one file locally in your browser to verify.

### Step 3 — Push to GitHub Pages

1. Create a new public GitHub repository (e.g. `sciento-eval`).
2. Copy all files from `build/out/` into the repo root (or a subfolder).
3. Enable **GitHub Pages**:
   - Go to **Settings → Pages**.
   - Source: `Deploy from a branch` → branch `main`, folder `/root` (or `/docs`).
4. After a minute, GitHub will confirm a URL like:
   `https://yourusername.github.io/sciento-eval/`

5. Each HTML file is then accessible at:
   ```
   https://yourusername.github.io/sciento-eval/author1_A.html
   https://yourusername.github.io/sciento-eval/author1_B.html
   ```

### Step 4 — Share URLs with experts

Send each expert **only the URLs for their assigned author's two outputs**.
The page shows purely the ScientoAI output — no navigation, no orchestration labels,
no links to other pages.

## 6. The `.md` Parsing Logic Explained

The JavaScript inside the template parses the downloaded `.md` automatically.
Here is how each section maps:

| `.md` element | HTML element rendered |
|---|---|
| `# Narrative CV: Prof. Name` (first `#` line) | Profile card title (`cv-profile-card`) |
| `### Theme Name` + description + `**Keywords**:` + `**Key Publications**:` | One `cv-cluster-card` in the grid |
| Everything after `---\n\n## Academic Biography` | `cv-narrative-card` body (full Markdown render) |

The parser is **tolerant of minor formatting differences** (e.g. missing
Publications section for a theme, different line endings).

## 9. Troubleshooting

| Problem | Solution |
|---|---|
| Themes section is empty | Check that the `.md` has `### ThemeName` headings under `## Thematic Research Areas` |
| Biography shows raw markdown text | Ensure `marked.js` loads (needs internet). Test with DevTools network tab. |
| Backtick or `${` in the CV breaks the page | The `build.py` `escape_for_js_template_literal()` function handles this; re-run the script |
| Page looks unstyled | The HTML is self-contained; verify the `<style>` block was not accidentally truncated |
| GitHub Pages 404 | Wait 1–2 minutes after enabling Pages; check the repo is public |
| Different line endings on Windows | Python's `read_text(encoding="utf-8")` normalises line endings automatically |

HTML table. Experts never see it since they only receive direct file URLs.

```html
<!-- index.html (optional, for your own use) -->
<!DOCTYPE html>
<html lang="en">
<head><meta charset="UTF-8"><title>ScientoAI Eval — Index</title></head>
<body style="font-family:sans-serif;padding:2rem">
  <h1>Evaluation Pages</h1>
  <table border="1" cellpadding="8">
    <tr><th>Author</th><th>Output A</th><th>Output B</th></tr>
    <tr>
      <td>Author 1</td>
      <td><a href="author1_A.html">Open A</a></td>
      <td><a href="author1_B.html">Open B</a></td>
    </tr>
    <!-- repeat for each author -->
  </table>
</body>
</html>
```
